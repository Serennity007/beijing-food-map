## 第一幕 · 找一家店（地图首页，不登录就能讲）

1. 打开 `/map`，默认视野是北京，底图是真实 OpenFreeMap 瓦片。
   - **讲解词**：「先看地图本身。点位是服务端按视野网格聚合的，缩放到 15 级以下看聚合数、以上看单店 —— 聚合与展开的口径由引擎决定，前端不参与算。」
2. 顶部切「贵州菜 / 西南风味 / 北京其他」，再选一个预算档，抽屉里列表跟着变。
   - **讲解词**：「先看地图本身。点位是服务端按视野网格聚合的，缩放到 15 级以下看聚合数、以上看单店 —— 聚合与展开的口径由引擎决定，前端不参与算。」
   - 「北京其他」这一视图放的是**北京常见但非西南菜系**的店型（烧烤、小龙虾、铜锅涮肉、传统小吃、面馆、烘焙、粤式茶点、日料、社区火锅）。菜系分类是**产品分类不是行政地理**，一家店可以带多个标签，按门店 ID 去重计数。
   - **屏幕上应出现**（本轮实测）：`测试·黔江酸汤粉（望京店）`、徽标 `贵州菜`、`社区推荐 3/3`、`推荐菜：凯里红酸汤鱼、花溪牛肉粉`、`用户报告人均 ¥68（3 人报告）`，两个按钮 `看依据` / `导航`；切到「北京其他」能看到 `测试·北新桥烧烤`、`测试·簋街麻小`、`测试·老北京铜锅涮肉`、`测试·护国寺小吃`、`测试·西单粤式茶点` 等。
   - **必须说清**：这些店名、地址、坐标、人均与票数**全部是合成占位**，前缀「测试·」与 `is_test_data=true` 就是为此而设。别把它们当真实商家介绍，也不要现场去掉前缀。
3. 点「待验证图层」。
   - **讲解词**：「这一层是显式开启的，空心标记，放的是**地点还没核验**的门店 —— 包括用户刚提交的建店申请。它永远不混进默认好店层，这是产品承诺：我们不做'没有好店就先凑数'。」

## 第二幕 · 判断值不值得吃（门店详情）

4. 点任意一家店的「看依据」。
   - **讲解词**：「这一屏回答的不是'几分'，而是'凭什么推荐'。社区票的口径、时间窗、有没有编辑背书、以及不达标的具体原因，全部由引擎算好后原样给出来。」
   - **屏幕上应出现**：`推荐依据` 区块里的 `社区：已达标 / 尚未达标`、`近 180 天窗口 <起> ~ <止>，推荐 X / 一般 Y / 不推荐 Z，共 N 张有效独立票`、`规则版本 recommendation-v1。收藏、点赞和浏览都不计入票数。`
5. 找一家不达标的店（例如第一幕待验证层里的）。
   - **屏幕上应出现**（本轮实测）：`这家店暂不在默认好店图层。` 以及 `不符合项：无有效推荐来源`。

## 第三幕 · 「这家店你们还没收录」（建店申请 → 地点核验）★ 本轮新增

6. 退出登录，或换一个没登录的浏览器窗口，进 `/submit`，在搜索框输入一个不存在的名字（例如 `演示动线新建店`）。
   - **屏幕上应出现**（本轮实测）：`没有匹配的已收录门店。如果这家店确实还没被收录，可以提交建店申请；审核员核验地点之后它才会进入待验证图层。` 下面是按钮 `申请新增这家门店`。
   - 若命中内置的地点候选，还会看到 `地图地点候选（1）`，条目带 `候选地点（未入库）·<检索词>` 与 `演示合成坐标，非真实门店位置`，按钮 `以此候选新建门店`。
   - **讲解词**：「第三方地点候选**只进入建店流程**，不会自动入库、更不等于好吃。」
7. （更快的路径）在地图上点一下空白处，状态条会出现 `已选点 116.4046, 39.9057（GCJ-02）` 与 `在这里新增门店` —— 点它直接进投稿页，建店表单已展开、坐标已预填，不用手打经纬度。
   - **讲解词**：「坐标口径全程 GCJ-02；MapLibre 底图是 WGS84，转换只发生在出 SDK 的那一道边界上。」
8. 打开表单，先不登录直接点提交。
   - **屏幕上应出现**（本轮实测）：`需要先登录才能申请新增门店` + 去登录入口。表单里也写明：`当前部署没有地图选点，也没有真实供应商地点检索（缺高德 Key），所以需要手填坐标`。
8. 用 `U01` 登录，填：店名、地址、坐标（`116.4030 / 39.9350`）、勾一个菜系、来源说明 ≥10 字，提交。
   - **屏幕上应出现**（本轮实测，编号会变）：`建店申请 RC0004 已提交，门店 R0003 的地点状态为「待核验」，需人工核验后才可能进入好店地图。现在可以继续填写实吃投稿。`
   - 紧接着这家店**自动成为投稿对象**，卡片标 `地点待核验`。
   - **讲解词**：「注意这里的分层：投稿是'我真的吃过'，地点是'这家店确实存在、位置对'。两件事各有各的审核，互不替代。」
9. 换 `M01` 登录 → `/admin` → 顶部切到「地点核验」。
   - **屏幕上应出现**（本轮实测）：卡片 `演示动线新建店` / `待核验` / `RC0004 · 第 1 版 · v1` / `手动选点` / `门店地点 待核验` / `来源说明：…` / `提交人 测试食客01 · 坐标 116.40300, 39.93500（GCJ-02）`，按钮 `地点核验通过` `驳回`，以及理由输入框。
10. **先演示权限边界**：用 `M01` 自己再提交一条建店申请，回到队列看那条卡片。
    - **屏幕上应出现**（本轮实测）：`这条是你本人提交的申请：按规则不能自审，引擎会以 403 拒绝，请交给其他审核人员。` —— 按钮直接不给。
    - **讲解词**：「后台只是入口便利。这条把关在引擎里，改前端绕不过去。」
11. 回 U01 那条，点 `地点核验通过`。
    - **屏幕上应出现**：卡片变 `已核验通过 · v2`，尾部 `该申请已处理完成，状态不可回退；需要改地点请在「门店状态」里操作并写明理由。`
12. 打开这家新店的详情页。
    - **屏幕上应出现**（本轮实测）：`地点核验：已核验 <今天>` 但**同时** `这家店暂不在默认好店图层。` `不符合项：无有效推荐来源`。
    - **讲解词（这场演示的题眼）**：「核验通过只解决'这家店在哪里、是不是真的'。能不能上好店地图，还要三个独立自费吃过的人投推荐票，或者编辑实吃背书 —— **地点核验 ≠ 好吃达标**，这两件事我们从不合并。」
13. 用 `U01` 进 `/me`。
    - **屏幕上应出现**（本轮实测）：`我的建店申请（1）` · `已核验通过` · `第 1 版 · RC0004` · `门店地点：已核验`，底部一句 `申请通过只代表地点核验通过，能不能进好店地图仍取决于社区票或编辑背书；这两件事由规则分开判定。`

> 可选加演（同一幕内）：驳回一条 → 理由回传给作者 → 作者「补充材料重新提交」→ 同一候选 `第 2 版` 回到待核验；
> 或演示重复提交 —— 同一个人再提同一家店，回执会变成 `已有相同的待核验申请（RC…），这次没有重复建店`。

## 第四幕 · 我吃过，写一条反馈（投稿 → 内容审核）

14. `U02` 登录，对一家已有门店写投稿（推荐态度 + ≥20 字理由 + 至少一道菜 + 一张演示图片 + 利益披露）。
    - **讲解词**：「图片不是相册上传，是服务端登记的合成素材并绑定账号 —— 演示不接真实对象存储，所以隐私页也只写我们真做到的那部分。」
15. `M01` 在 `/admin` 的「待审队列」通过它。
    - **上一轮记录**：门店页显示「第 2 版」，审计日志留下版本流转记录；待审期间**旧的已批准版本继续公开并继续计票**。

## 第五幕 · 攒我自己的美食地图（清单 → 发布 → 分享 → 撤销）

16. `U01` 在「我的地图」新建清单、加店、写私人笔记，预览即快照，提交发布申请。
17. `M01` 通过发布申请 → 打开分享链接（种子自带 `demo-token-1` 可直接看效果）。
18. 作者点「撤销分享」→ 同一链接立即失效。
    - **上一轮记录**：撤销后显示「链接无效或已撤销」；旧 token 永久失效，`publication_generation` 递增会作废此前全部待审发布申请。
    - **讲解词**：「分享出去的是**不可变快照**，不是清单的实时视图。别人存下的链接不会因为我又改了清单而变样，我撤销就是真撤销。」

## 第六幕 · 有人报错怎么办（纠错与举报）

19. 门店页「纠错／举报」提交一张工单（例如闭店搬走）。
20. `M01` 在「举报复核」看到队列，卡片带门店名与状态中文标签，可一键跳到「门店状态」预选该店。
    - **上一轮记录 + 本轮补充**：本轮把举报卡片的中文措辞统一到 `contracts/enums.ts`，前台后台读同一份标签。
    - **诚实说明**：举报**工单的处置状态流转还没做**（blockers C9 的写侧），所以这里只演到"看得见、跳得过去"，不要说成"已经闭环处理"。

## 收尾一句话

> 「地图上的每一个点位都答得出两件事：**它在哪里、谁在凭什么推荐它**。用户能贡献新店和新反馈，但贡献不等于上榜 —— 地点要核验，推荐要独立票，作者不能自审，撤销不可恢复。」

## 讲这些时必须守口径

- 这是**演示版**：门店、图片、实吃记录、票数**全部是合成测试数据**（店名前缀「测试·」、`is_test_data=true`），不代表任何真实餐馆。
- `release_ready：否`。真实对象存储、可水平扩展的持久化、举报处置闭环、地图 Key 与真机适配都还没有。
- 不要说"已上线/可部署给顾客用"；被问到就指 `docs/status.md` 与 `docs/blockers.md`。

## 翻车预案

| 症状 | 处置 |
|---|---|
| 自检有 FAIL：站点不可达 | 演示站没起。双击「一键演示」，看窗口里打印的端口号（4173 被占会自动往后换） |
| 自检报「构建模式与运行方式不一致」 | 产物是另一种模式构建的。去掉 `--skip-build` 重跑一键演示，它会重新构建 |
| 后端模式起不来 | 一键脚本等 30 秒会提示退回静态模式：`node scripts/serve-demo.mjs`（功能同一份引擎，数据在本机浏览器） |
| 地图白屏没瓦片 | 底图走公共瓦片，需要外网。断网时列表与详情照常，只是没底图；别当成后端故障 |
| 静态模式刷新后像"掉登录" | 数据在本机 localStorage，清过站点数据就会回到初始种子。换浏览器窗口即可复原 |
| **改了种子但页面上看不到新店** | 同一个 origin 的 `localStorage['qianwei.state']` 存着**旧快照**，`StaticClient` 会优先读它，新种子不会覆盖它。演示前清一次本站点数据（或控制台执行 `localStorage.removeItem('qianwei.state')` 后刷新）。后端模式没这个问题，它每次读库 |
| 手机打不开局域网地址 | 手机与电脑需同一 Wi-Fi；`169.254.*` 那个地址不可用（脚本已过滤）。仍不行就是路由器隔离 |
| 建店提交一直报坐标/地址不合法 | 坐标必须在北京范围内（GCJ-02），地址 5—120 字，来源说明 10—300 字。这些是引擎判的，不是前端限制 |
| 队列里看不到刚提交的候选 | 确认审核账号有 `moderator`/`admin`；本人提交的会显示"不能自审"而不是消失 |
| 演示到一半想恢复初始数据 | 后端模式：删掉 `work\demo-*.sqlite` 重起即由种子重建。静态模式：清本站点数据。默认演示库另有「复原演示数据」 |
