## implemented

**领域引擎（`packages/contracts`，唯一规则实现处 —— 页面不得重算）**

- 49 家合成门店 + 9 个合成账号 + 128 条合成实吃记录，全部 `is_test_data=true`；`NODE_ENV=production` 下 Store 拒绝装载。品类覆盖贵州/川/渝/滇之外的常见北京餐饮（烧烤、小龙虾、铜锅涮肉、传统小吃、面馆、烘焙、粤式茶点、日料板块、社区火锅），走「北京其他」视图。名字、地址、坐标、人均与票数都是合成占位。
- 默认好店层谓词：资料可公开 AND 地点 `VERIFIED` AND 营业 `OPEN|UNKNOWN` AND 风险 `CLEAR` AND（社区 `QUALIFIED` OR 编辑 `ACTIVE`）。不满足时详情接口列出**具体不符合项**。
- 社区计票 `R ≥ 3 且 4R ≥ 3T`，窗口是 Asia/Shanghai 含两端的 180 个自然日；读时重算过期（不依赖新投稿）；撤回立即退出公开与计票且历史版本不复活；低 revision 不能覆盖已批准的 revision；利益披露非"无关联"的公开披露但不计独立票；编辑背书需非作者核验。
- 服务端固定网格聚合（`cellDegForZoom` 分档），点击展开带 `expansion_bounds`；快照/`queryKey` 过期 409 `QUERY_EXPIRED`；列表上限 200；写操作乐观锁 `expected_version`。
- 坐标全程 GCJ-02，只在 MapLibre 渲染边界转 WGS84；高德原样使用。
- **新门店候选与地点核验**（方案见 [design/restaurant-candidates.md](./design/restaurant-candidates.md)）：候选是独立实体，不与投稿版本混用；创建候选同时落一家 `place_status=PENDING` 门店，默认层谓词未改动即把它挡在外面；同作者重复提交复用同一条候选；命中已有门店只给重复提示（provider+poi_id / 同名 ≤150 m / 同名但远），不自动合并不自动驳回；驳回必填理由并回传作者；补材料 `revision+1` 回待核验，只有换坐标才递增 `location_version`；并入走门店合并（仅 admin）；本人提交的候选在 `decideCandidate` 与 `patchRestaurantStatus` 两处都不能自审。
- **举报工单处置闭环**（见 decisions D19）：同人+同店+同类型+**同 `feedback_target`** 且未结案的重发返回原单；门店页每条公开反馈都有"举报这条内容"，工单可指向某条反馈的某一版（`VF002#v1` 形状）或只举报整店；`reportQueue(sessionId, status?)` 待处理优先、上限 200、带门店名与 `is_reporter_self`；`decideReport` 走 `REPORT_TRANSITIONS`（终态无回退边）、结案与驳回必填处理结果、版本不符 409、**举报人不能处置自己的工单**，且处置不改门店状态；`result_note` 只能由处置动作写入。
- 时间展示统一走 `shanghaiDay` / `shanghaiDateTime`（与 `shanghaiToday` 同一套 `Intl` 口径），页面不截 UTC 字符串（decisions D20）。

**网页端（`apps/web`，11 个页面）**：地图（筛选/搜索/抽屉三档/点空白选点）、门店详情、投稿（含建店申请与补材料）、我的（清单/反馈/举报/建店进度/注销）、清单编辑与发布/撤回、分享只读页、`/login`、`/admin` 审核台（待审队列、地点核验、举报复核、门店状态、编辑背书、审计日志；合并仅 admin）、法律页、404。地图适配器双实现（MapLibre 公共瓦片 + 高德 JS API 2.0），无 Key 时走瓦片兜底。所有中文标签取自 `contracts/enums.ts`，建店表单只有 `features/candidates/CandidateForm.tsx` 一份。无障碍：全站第一个可聚焦元素是「跳到主要内容」（聚焦才现身，目标是 `<main id="main" tabIndex={-1}>`），所有 chip 型开关带 `aria-pressed`，MapLibre 画布 `aria-label` 为中文并写明方向键/缩放与"回车不在此选点"。

**演示后端（`apps/api`）**：`node:http` 外壳 + `node:sqlite` 文档表 + SQL 迁移 + OpenAPI 3.0 全量覆盖（有测试强制与路由表一一对应）+ HMAC 签名会话 Cookie + 登录限流 + Origin/Sec-Fetch-Site 跨站写拦截 + 图片鉴权直出 + 审计日志 + 注销清除任务排空（启动时与每秒，失败回滚重试）。**44 条 method+path 操作 / 38 个不同路径**。新增实体种类不需要新迁移（`documents` 是 `kind/id/body` 通用形状）。

**运行模式**：`VITE_API_BASE` 为空 → `StaticClient`（浏览器内跑同一引擎，落 `localStorage`）；非空 → `Http`。页面层只依赖 `ApiClient` 接口，规则不存在第二套。两种模式下注销都会立即清掉本机投稿草稿。
