# 真实门店数据 · 收集与核验工作区

这里是**真实数据的暂存区**。硬约束：不虚构门店/探店/票数；未核验的数据**不进引擎、不进任何公开图层**。

## 文件说明

| 文件 | 是什么 |
| --- | --- |
| `web-candidates-20260924.json` | 网页检索来的 9 家真实北京贵州/云南菜馆，**只存店名与来源指针**，坐标/地址为 null，`verified:false` |
| `amap-candidates-template.json` | 高德来源的手填模板（扫街榜人工记录用），复制一份填写后交给导入脚本 |
| `amap-candidates-<日期>.json` | 导入脚本生成的暂存产物（生成后属于数据，手工核验时直接改它） |

## 从高德拿数据的两条路

1. **高德开放平台·搜索POI**（推荐，批量）：注册 [高德开放平台](https://lbs.amap.com/) → 创建应用 → 拿「Web 服务」Key → 用「搜索POI 2.0」按关键词/矩形检索（如关键词"贵州菜"，城市北京）→ 把响应 JSON 存盘 → 跑：
   ```bash
   npx tsx scripts/import-amap-candidates.mts 高德导出.json
   ```
   脚本做三件事：解析 `pois`、校验坐标（GCJ-02 合法性 + 北京范围）、按 poi_id 去重；产出暂存文件。**Key 属于凭据，不进仓库**（放本机环境变量或命令行，别写进任何文件提交）。
2. **扫街榜人工记录**（少量、精选）：在高德 App 里逛扫街榜，按 `amap-candidates-template.json` 的格式记录店名/地址/坐标（App 内地点详情页可以拿到坐标与 poi_id）→ 同样交给上面的脚本或直接手工并入暂存文件。

## 三道没过的门（脚本和模板都绕不过去，只能人来）

1. **人工核验**：坐标格式合法 ≠ 店真在那里。门牌、位置、菜系归类要实地或凭可靠来源确认。
2. **在营确认**：第三方条目可能已闭店/搬迁，快照不等于当前事实。
3. **数据条款**：高德开放平台对存储与展示有约定，确认前只保留最少字段（店名/地址/坐标/poi_id），不搬评分、评论、榜单文案、图片。

## 核验通过之后

人工确认的条目走产品自身的正规流程入库：**建店候选（带 `provider:'amap'` + `poi_id`，引擎自动做候选去重）→ 审核员地点核验**。这样每家真实门店都带着完整的审计链路，而不是绕过规则的批量写入。
